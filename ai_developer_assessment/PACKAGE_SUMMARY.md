## 🎯 How to Use This Package

### Before Your First Interview (10 minutes)
1. Read `QUICK_START.md` (3 min)
2. Skim `SOLUTION_GUIDE.md` to know the bugs (5 min)
3. Print `INTERVIEW_SCORECARD.md` (2 min)

### During Each Interview (60 minutes)

#### Setup (2 min)
- Welcome candidate
- Explain interview structure
- Share screen/check setup

#### Part 1: Debugging (15 min)
- Send candidate `buggy_model_api.py` and `CANDIDATE_INSTRUCTIONS.md`
- Watch them debug while referring to `SOLUTION_GUIDE.md`
- Score on `INTERVIEW_SCORECARD.md`

#### Part 2: Questions (45 min)
- Ask questions from `INTERVIEW_QUESTIONS.md`
- Score responses on `INTERVIEW_SCORECARD.md`
- Leave time for candidate's questions

#### Wrap Up (3 min)
- Thank candidate
- Explain next steps

### After Interview (5 minutes)
- Complete `INTERVIEW_SCORECARD.md`
- Calculate score (90-100: Strong Hire, 75-89: Hire, 60-74: Maybe, <60: No Hire)
- Share with hiring team

## 🎓 Assessment Design

### The Debugging Exercise Tests:

**Technical Skills:**
- ML production issues (training/serving skew) ⭐
- API design and error handling
- Data validation
- Performance optimization
- Observability

**Soft Skills:**
- Problem-solving approach
- Communication and explaining reasoning
- Transparency (admitting uncertainty)
- Prioritization and judgment

### The Interview Questions Test:

**System Design:**
- End-to-end architecture
- Scalability and performance
- Trade-off analysis

**MLOps:**
- Deployment strategies
- CI/CD and automation
- Monitoring and observability

**Soft Skills:**
- Assertiveness (pushing back on bad requirements)
- Ownership and accountability
- Handling ambiguity
- Collaboration

## 📊 What Good Looks Like

### Strong Candidate (Hire)
✅ Finds 6+ bugs including the ML-specific ones  
✅ Explains impact clearly  
✅ Asks clarifying questions  
✅ Admits when uncertain  
✅ Systematic debugging approach  
✅ Thinks about production implications  
✅ Can design end-to-end systems

❌ Shallow system design knowledge  
❌ Accepts bad requirements without question

## 🔧 Customization Options

### Want to Focus More On...

**MLOps?**
- Add Docker/Kubernetes questions
- Include CI/CD pipeline design
- Add monitoring tools questions

**ML Theory?**
- Add algorithm questions
- Include model architecture design
- Ask about specific techniques

**Coding?**
- Add live coding problems
- Include algorithm challenges
- Request implementation of specific features

**System Design?**
- Add whiteboarding exercises
- Include scaling scenarios
- Ask about distributed systems

### Want to Adjust Difficulty?

**Make Harder:**
- Add more subtle bugs (race conditions, memory leaks)
- Reduce time (10 min debugging)
- Add follow-up coding tasks
- Require working fixes, not just identification

**Make Easier:**
- Reduce number of bugs (focus on 4-5 key ones)
- Provide more context
- Allow reference materials
- Give hints if stuck

## 💡 Pro Tips

1. **Create Safety**: Tell candidates it's okay to say "I don't know"
2. **Watch, Don't Help**: Let them struggle to see their process
3. **Probe Depth**: Ask "why" and "how would you" questions
4. **Listen for Values**: Do they care about users, quality, collaboration?
5. **Trust Your Gut**: Technical skills can be taught; values are harder to change
